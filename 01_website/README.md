# CAR PRODUCE ONE — Webサイト

React + Viteの静的サイトです。ChatGPT Sitesには依存しません。

## 起動

ルートの `../OPEN_PREVIEW.cmd` を開くか、このフォルダで以下を実行します。

```text
npm ci
npm run dev
```

ローカルURLは http://127.0.0.1:5173/ です。
`npm run build` で `dist` を生成、`npm run preview` でビルド済みサイトを確認できます。公開先は第7段階で設定します。

## 第5段階で完成した範囲

6サービスを説明付き一覧にし、各項目から相談セクションへ移動できるようにしました。
工具と雑誌の3Dイメージを使った店舗紹介、住所・地図リンク、電話・LINE・QRコード、フッターナビゲーションを実装しました。

## 交差点からの接続

サイトの最初の走行は、新しい街並みを使った20秒・160mのループです。スクロール開始時の再生位置から共通地点まで走り、16秒の「減速→90度右折→直進」を経て既存の到着映像へ接続します。街区は固定し、車と車載カメラを同じ経路で動かしています。

- `src/JunctionTransition.tsx`: 右折映像のスクロール制御。
- `src/junction-transition.ts`: 20秒・30fpsの時間対応と動画の版番号。
- `public/media/junction/{desktop,mobile}/drive.mp4`: 600フレーム・30fpsの走行ループ。
- `public/media/junction/{desktop,mobile}/turn.mp4`: 481フレーム・30fpsの右折と合流（16秒＋終端1フレーム）。

初期区間は論理タイムラインの先頭18%です。実際のスクロール距離は `journey-scroll.ts` で変換します。到着映像への接続点で進む速さが連続するよう時間を変換しています。工具・雑誌・モニターの停止位置は維持しています。
冒頭へ戻る際はスクロール用のシークを解除し、動画全体の自動周回へ戻します。動画と冒頭画像のURLに`JUNCTION_MEDIA_VERSION`を付け、差し替え前のキャッシュが残ることを防ぎます。

現在は横640×360・縦360×640、Cycles 16 samplesのテスト品質です。到着後の既存動画は8fps／24fpsを使用しています。右折の最後の1フレームには、同じカメラ位置の到着動画の先頭画像を使用し、確認用動画間の画質差を抑えています。この画像処理は3D原本には含みません。

最新MASTERには、カフェ・ホテル・オフィス・ガレージ・閉店中の店舗・奥まったロビーの6種類の1階、大小24面の追加広告、8種類の新しい広告画像、背後の11棟、街路樹8本、駐車区画の車1台、バス停と街路設備を配置しています。車は道路中心から2.6m左の車線を走ります。
街区と濡れた路面の模様を160m周期にそろえています。検証では始点・終点だけでなく、圧縮後の最終フレーム→先頭フレームの画像差を通常の隣接フレームと比較します。

`npm test`は23件。メディアの照合情報は`../02_render/reports/junction-media-manifest.json`、接続と周回の検証結果は`junction-media-validation.json`、モデルの検証結果は`junction-scene-validation.json`です。ブラウザーでの操作記録は`junction-site-verification.json`に保存しています。
以前の方式のコード・動画・検証記録は`../90_archive/connection_slide`に保管しています。最終画質の全編描画はまだ実行していません。

## 右折後のスクロール速度

右折前の直進は従来のスクロール量を維持する。右折中は、映像を同じだけ進めるためのスクロール量をsmoothstepの積分で1倍から2倍へ徐々に増やす。右折完了後は、本編・停止場面・モニター接近を含めて従来の2倍のスクロール量とする。

停止時刻や映像素材は変更せず、物理スクロール距離と論理タイムラインを単調な対応で結ぶ。逆スクロールでは同じ対応を逆にたどる。開始時の走行ループ位置に応じて右折開始位置とページのスクロール範囲を決め、場面ボタンも同じ変換を使う。

`data-scroll-scale` は実際にDOMへ反映した距離倍率を保持する。スクロール開始直後にループ位置が確定してページの高さが変わっても、基準距離を現在の高さ／倍率から求めることで、映像位置の飛びを防ぐ。

37件のテストで、右折中の単調な減速、境界での速度連続、右折後の距離2倍、逆スクロール、場面移動を確認。PC幅・スマートフォン幅で場面ボタンと本編への接続も確認済み。


## 本番モニター合成と時間制御の接続（2026-09-11）

現在の配信版は `final-table-approved-20w-monitor-power-04`。上記の確認用画質・HTML追従の記述は旧段階の記録です。全動画は30fps、本番画質で、モニターの停止・接近映像は16-bit sRGBの本番フレームへ画面内容を合成し、H.264 8-bit / HEVC 10-bitへ書き出しています。カメラ映像中にHTMLを重ねないため、文字だけが一拍遅れる経路はありません。

- `src/PortalHandoff.tsx` / `portal-timing.ts`: モニターが視界を覆った位置で約700msの独立した演出を開始。最初の150msは横ずれとノイズ導入、300msで表示を切り替え、430–700msでノイズの密度・強さ・横方向の乱れが画面全体で滑らかに収束します。粒状ノイズは毎フレーム更新し、手を止めても完了します。
- 完了時は残りの接近区間を終えてサイト先頭へ着地します。先に本文までスクロールしていれば、その位置を保ちます。逆方向には18フレーム分の余裕を設けて再発火を防ぎ、明確に戻った場合に退出演出を実行します。
- メニューによる直接移動は演出をキャンセル。動きを抑える設定ではノイズを再生しません。
- `../02_render/assets/monitor-hero.png`: モニターへ合成する1280×720レイアウトの2倍解像度画像。見出し・ヒーローの内容を変更したら再生成して該当動画を再合成します。
- `../02_render/scripts/composite_monitor.py --version <新しい版名>`: 既存の本番PNGからportal、monitor-idle、monitor-approachを合成・検証。他の動画は同じ内容を参照するハードリンクで保持します。既存版への上書きを拒否し、確認用のマニフェストを出力します。検証後、そのJSONを `src/production-media.json` に反映して `npm run build` を実行します。

実行ブラウザでPC・スマホ相当の表示サイズにて停止後の約700ms完了、ノイズの変化、逆方向、早いスクロール位置の保持、メニューによる中断、動きを抑える設定を確認しました。iPhone/Safari実機確認は別途必要です。

モニター点灯は `MonitorApproach.tsx` の78–81秒の接近区間に接続。元フレーム2370–2424（79–80.8秒）で画面内容をsmoothstepで点灯し、停止・接近映像へ明るさを保って接続します。該当区間へ近づくと読み込み、静止ループでは点灯を繰り返しません。四隅の座標は本番Blenderシーンから出力し、既存2430フレームの追跡データとの誤差を確認しています。

PCのモニター接続はノイズを使わず、モニターが視界を覆ったところで通常サイトへ移行します。スマートフォンのノイズは450ms（導入100ms、切り替え190ms、収束280–450ms）です。

スマートフォンはノイズの450ms中だけスクロール位置を固定します。ホイール・touchmove・スクロールキー・慣性移動を抑え、完了・中断・端末切り替え時に元のスタイルと操作へ戻します。PCの最新実装は下記の連続投影方式です。


## PCの連続投影による接続（2026-09-11）

PCは `DesktopPortal.tsx` と `desktop-projection.ts` を使用します。通常サイトの同じMainHero DOMを終端の四隅から逆算して配置し、元フレーム2340–2700のモニターへ射影します。終端は厳密な恒等行列になり、固定配置から通常フローへ戻します。文字はブラウザーで描画し続けます。

動画の提示フレームをrequestVideoFrameCallbackでCanvasへ取り込み、その画像と同じフレーム番号からDOMの投影を一度に更新します。背景はレイアウト・DPRごとにCanvasへ描画し、接続前後の合成による色の微差を防ぎます。読み込み失敗・終端待機のタイムアウトでは本文を利用可能にします。

PC用の画面未合成素材は `src/desktop-portal-media.json` が参照する `public/media/production/desktop-live-screen-05/` にあります。元データは `02_render/output/final-table-approved-20w/exports/delivery-srgb-nvenc-02/desktop/` のportalとmonitor-idleです。スマートフォンは従来のpower-04素材と450msのノイズ・スクロール固定を使用します。従来の画面合成に関する記録はスマートフォン用として参照してください。

`npm test` は射影・終端・点灯を含む54件。`npm run build` はPC用4動画と2ポスターも照合します。`tests/desktop-portal-fixture.html` は同じMainHeroとDesktopPortalで終端前後を比較する開発用画面で、配布ビルドには含みません。

Windows Edgeで16:9・16:10・21:9・正方形など9つの画面幅／DPR条件と実ブラウザーズーム75–200%の6条件を比較し、終端前後の画像差分は15条件すべて0でした。通常・高速・逆スクロール・停止・リサイズと、スマートフォン320/390/430pxの既存版との画像一致も確認しました。Safari／Firefoxおよび実スマートフォンでは未検証です。


## スマートフォンの中央進入と左右の背景（2026-09-11、最新）

スマートフォンも同一HTMLの連続投影へ移行しました。従来の450msノイズとスクロール固定は通常の接続では使用しません。中央は通常のスマートフォン用MainHeroを維持し、左右のモニター領域に工具の3Dイメージと提供写真の車体を配置します。左右は暗さ・彩度・マスクで背景へなじませ、終端でビューポートの外へ抜けます。左右には操作要素を配置しません。

- `DesktopPortal.tsx` はprofileに応じて1920×1080／1080×1920の動画と四隅を扱う共通レンダラーです。`mobile-screen-tracking.json` は2340–2700フレームを含みます。
- `mobile-portal-media.json` は画面未合成の `public/media/production/mobile-live-screen-06/` を参照します。元素材は `02_render/output/final-table-approved-20w/exports/delivery-srgb-nvenc-02/mobile/` のportal・monitor-idleです。
- 左右の素材は `public/media/monitor-wings/`。tools.webpは既存の本番tools-idleポスター、car.jpgは提供素材 `03_reference/source_materials/photos/5.jpg` のコピーです。トリミングと暗さはCSSで調整します。
- 動画シークはフレーム中央を指定し、表示中のrVFCに加え非表示中のseekedでも画像と投影を更新します。本文から映像へ戻ったときは省略状態を解除します。
- 表示領域の高さが変わっても接近位置を保持し、端末の縦横切り替え時にprofileを更新します。背景Canvasのスマホ用解像度を1倍に抑え、画面外の大きな背景によるメモリ消費を抑えます。

検証は60件の単体テスト、追加の縦動画4本のSHA-256照合、型チェックとビルド。Windows Edgeのスマホ相当表示で320/375/390/430pxのタッチ・高速/逆スクロール・停止・本文リンク・縦横回転・高さ変更を確認しました。終端比較は5条件すべて画像差分0、描画フレーム番号の不一致0でした。動きを抑える設定でも本文へ進めます。iPhone/SafariおよびAndroidの実機では未検証です。

# 店内映像の分割配信

店内を巡る `route` は30fps・2,430フレームで、スクロール位置から決まる0〜81秒の時間軸を使います。HEVC・H.264ともに5ファイルです。画面の向きによって素材を切り替えます。

## 配信ファイル

`public/media/videos/<profile>/route/` に置きます。

| 形式・ファイル | 全体のフレーム範囲（両端を含む） | フレーム数 |
|---|---|---:|
| `<codec>-part-1.mp4` | 0〜1211 | 1212 |
| `<codec>-part-2.mp4` | 1212〜1511 | 300 |
| `<codec>-part-3.mp4` | 1512〜1811 | 300 |
| `<codec>-part-4.mp4` | 1812〜2111 | 300 |
| `<codec>-part-5.mp4` | 2112〜2429 | 318 |

`<codec>` は `hevc` または `h264`。前半40.4秒は維持し、後半は10秒・10秒・10秒・10.6秒へ分割します。

40.4秒の分割点は、工具の説明中に飛ばす34.2〜43.2秒の区間内です。通常の操作でも分割点の両側へ移るため、先読みと逆方向への切り替えは必要です。

公開用の動画44本はすべて通常Gitで管理します。`.gitattributes` でLFSフィルターとテキスト変換を無効にし、各ファイルが100MiB未満であることをビルド時に検証します。

## マニフェスト

`src/media/manifests/journey.json` の形式ごとのレコードは、単一ファイルの `src`、または `segments` を持ちます。各セグメントは `src`・`startFrame`・`frames`・`bytes`・`sha256` を持ち、フレーム範囲は欠落・重複なしで全体を覆います。

分割前のハッシュと容量は `source_file` に残します。元のエンコード情報は再圧縮を行っていないことを示す元動画の情報です。配信ファイルそのものの照合には、各セグメントのハッシュと容量を使います。

## 再生とモニター投影

`ScrubMediaVideo` と `segmented-playback.ts` が、最大2つの通常の `<video>` を制御します。HEVC非対応時とHEVCのデコード失敗時にはH.264へ移り、最新の全体時刻を維持します。

- 全体のフレーム番号からセグメントを選び、`全体フレーム − startFrame` をローカルフレームへ変換します。MP4の丸めで前のフレームを選ばないよう、フレーム中央へシークします。
- 起動時に前半を取得し、操作解放後に後半を先読みします。境界の12秒手前では隣のデコーダーも準備します。2つのvideo要素を交互に使い、現在のフレームを表示している要素は先読みで上書きしません。移動方向の隣の区間を非表示の要素で準備します。使用したBlobはセッション内で保持し、逆方向ではHTTPの再取得をせずに再接続します。
- 切り替え先の要求フレームがデコードされるまで、表示中の動画を保持します。非表示の指定には `visibility` を使い、分割境界で透明度のフェードを発生させません。
- シーク中の追加入力は最新の要求へ集約します。`seeked`・`loadeddata` と `requestVideoFrameCallback` の両方からデコード済みのフレームを確認します。
- 表示先を切り替えたときは `routeframe` イベントも通知します。すでにデコード済みのフレームへ戻る場合、新しい `seeked` が発生するとは限らないためです。

`MonitorPortal` は表示中の動画を選び、ローカル時刻に `data-media-start-frame` を加えた**全体のフレーム番号**で投影します。各区間の `currentTime` をそのまま投影へ渡すと、その区間の開始位置分ずれます。最後の区間の `startFrame` は2112です。route末尾の画像をモニター待機のフレーム2430として扱う既存の対応も維持します。

## 再生成と検証

レンダリング元のHEVC・H.264は分割せず `02_render/output/` に保持します。`package_media.py install` はコピー後に `split_route_media.py` を実行し、分割済みの配信ファイルへ置き換えます。

分割はキーフレームから圧縮パケットをコピーし、ローカル時刻だけを0開始へ変換します。全パケットとタイムスタンプ、全デコードフレームの一致、色・フレーム数・fast-start・95MiB未満を確認してからマニフェストを更新します。Bフレームのある素材やキーフレームでない分割点は拒否します。

- 自動検証：`npm test`、`npm run build`、制作側の `test_split_route_media.py`。
- ブラウザー：[PC用](http://127.0.0.1:5173/tests/segmented-video-fixture.html)／[スマホ用](http://127.0.0.1:5173/tests/segmented-video-fixture.html?profile=mobile)。スライダーで分割点の前後を往復できます。
- 実際のページでは工具の説明前後、後半から前半への逆スクロール、モニターへの接近・退出、表示サイズの変更、HEVC失敗時の切り替えを確認します。

## 起動時の先読み

[動画ロード制御](video-loading.md)を参照してください。シーク用の動画は取得完了したBlobを再生し、MP4のRange取得とスクロールの競合を避けます。

## 切り替え時の下地保持

分割videoのactiveスロットを変更する直前に、表示中videoのデコード画像をCanvasへ保存する。Canvasはネイティブ動画の下、章別fallback画像の上に置く。次の動画レイヤーの描画が遅れても、別場面のfallbackが露出しない。通常表示はネイティブ動画を維持する。保存失敗時は旧スロットを隠さず、ステージングCanvasで既存の正常な保持画像を保護する。正逆両方向に適用し、メディア変更時は保持画像をリセットする。

Safariの提供録画で見られた約17～33msの雑誌コーナー画像の露出に対応する防御処理。シーク完了とコンポジター提示の内部順序は実機トレース未取得であり、この修正後のSafari実機検証は別途必要。

# 動画のロードとスクロール解放

## 起動条件

`useStartupLoading` が起動時の二段階ゲートを管理する。

1. 黒背景：街の動画の先頭から75%（20秒中15秒）が連続して `buffered` に入り、先頭フレームへ戻って表示可能になるまで操作を止める。`seekable` は取得済み判定に使わない。
2. 街の表示：街をミュート・インラインでループ再生し、半透明の進捗パネルを残す。右折動画、route前半（0〜40.4秒）、工具の待機ループを選択したコーデックで取得する。
3. 解放：上記の取得完了に加えて、右折・route・工具の動画から `loadeddata` またはデコード完了を確認すると操作を解放する。route前半は工具の静止時刻34.2秒を含む。

街のネイティブ先読みを進めるため、黒背景の裏でミュート再生する。75%が準備できたら先頭へ戻して街を表示し、店内前半の取得を開始する。ユーザーは初期表示を優先し、残り25%の取得が間に合わない場合のカクつきを許容している。全量取得に戻さない。街の残りのネイティブ取得と店内fetchはブラウザーの回線を共有するため、完全な帯域分離や街の無停止は保証しない。

第1段階は取得済みの連続秒数/動画の75%の秒数、第2段階は必須ファイルの取得バイト数/総バイト数を表示する。デコード待ちは99%以下とし、準備が整ったら次の段階へ進む。タイマーで進捗を偽装しない。

## 後半の区間ゲート

route後半は約10秒ずつの4区間。`download-gates.ts` が、前から順に未取得のファイルを探して前進の上限を決める。雑誌・モニターの待機ループ、portalにもその場面の手前でゲートを設ける。

- 未取得の区間へ進もうとすると、取得済み側の最終フレームで停止し、その区間の実取得率を表示する。
- `sampleJourney` は説明中の時間を飛ばすため、境界は動画時刻を単純に割らず、時間軸の逆引きで決める。フレーム丸めを考慮し、未取得区間の最初のフレームへ入らない。
- 取得が完了すると前進を許可する。過去のホイール量・ジャンプ先を再生しないので、カメラは自動で先へ進まない。
- 読み込み済みの範囲へ戻る操作は制限しない。本文へ直接移動して未読込の映像へ戻る場合は、逆方向にも区間ゲートを適用する。使用済みのBlobはセッション内で保持する。
- 境界の直前から隣のデコーダーを準備し、切り替え先のフレームが実際にデコードされるまでは表示中のフレームを保持する。

## 操作と復帰

入口では映像のスクロールを止め、入力は蓄積しない。ヘッダーとスマホメニューは全段階で操作でき、本文リンクは即座に入口ロックを解除して直接移動する。黒背景中のみ映像側をinertにし、街表示後は読み込み済みの行き先と背景の停止・再生を有効にする。未準備の映像ボタンはdisabledとし、準備中の表示を付ける。準備が完了すると通常のラベルへ戻り、自動移動はしない。動きを抑える設定や本文へのハッシュリンクは入口ゲートを通らない。本文や途中での画面幅変更でも入口へ戻さない。

HTTPエラー、途中で切れたレスポンス、30秒間データが届かない取得はエラーにする。再試行は取得セッションを作り直し、旧取得を中断する。エラー時は本文へ進む経路も提供する。自動再生が拒否された場合は背景再生ボタンを表示する。

移動中は必要な映像を優先する。デコードが250ms以上追いつかないと小さなローダーを表示する。routeの表示中フレームは次のフレームが用意できるまで保持する。モニター投影もportal未取得時には既存のスナップショットを使う。カメラ位置は引き続きスクロール位置だけで決まり、時刻経過で追いかけない。

## 取得・メモリ管理

`VideoDownloads` はURLごとに転送を共有し、完了したBlob URLをプレーヤーへ貸し出す。転送は1本ずつ。区間ゲートで操作を待っている場合、その区間の取得を最優先にする。別の動画の転送が進行中なら一時中断し、受信済みのバイト列と完了Promiseを保持する。中断した転送はHTTP Rangeで続きから再開し、206の開始位置・総サイズを検証する。サーバーがRangeを無視して200を返す場合は部分データを破棄して全体を取得し直す。操作解放後は各区間と待機ループを登場順に先読みする。先読み用デコーダーの要求も低優先度とし、現在必要な区間の取得を追い越さない。

背景先読みは保持容量160MiBを目安に止める。実際に表示に必要な動画はこの目安を超えて取得できる。現在使用中または使用済みのBlobは逆移動のためにセッション内で保持し、未使用の先読みデータから容量を整理する。したがって160MiBはブラウザー全体のメモリ上限ではなく、動画デコーダーの作業領域なども別に必要になる。プロファイル変更・再試行・アンマウントでは取得を中断し、Blob URLを破棄する。

## 検証

- `npm test`：URL共有、バイト進捗、優先順、途中切断、再試行、キャンセル、既存のスクロール・分割・投影契約。
- `npm run build` と `npm run verify:pages`：動画44本のハッシュ、分割範囲、個別100MiB未満、公開物1GB未満、Pages配下の参照。
- ブラウザー：黒背景→街→解放、ロード中の入力、背景停止、前後移動、通信失敗、本文への直接移動、サイズ変更、4 Mbpsで15秒分の読み込み後に店内取得が始まること、区間の前進制限と逆移動、H.264フォールバックを確認する。
- Safari実機は別途確認が必要。EdgeのスマートフォンエミュレーションをSafariの検証結果として扱わない。

## 準備中表示とボタン

ローダーは全段階でヘッダー下端から12px下の中央へ配置する。ヘッダー高はResizeObserverで測り、画面幅や文字拡大へ追従する。黒背景でもヘッダー・メニューはローダーより前面に置く。ローダーはリング・説明・％のみの横並びを基本とし、通常の背景再生ボタンは映像側の既存操作部へ集約する。黒背景で自動再生が拒否された場合のみ、ローダー内にも再生操作を残す。

未準備のボタンの％は、中央パネルと同じ「現在読み込んでいる区間」の進捗を表示する。異なる集計範囲の数字を並べない。十分に高さのない画面ではヘッダーと導入文をコンパクトにし、ナビゲーションとの重なりを防ぐ。

## 本文へ直接移動した後の逆スクロール

本文へスキップしたことを、映像をすべて訪問済みであることと混同しない。未取得のportalへ戻ろうとした場合は本文の先頭位置を保ち、終端フレームを取得・デコードしてから逆方向を許可する。その間も本文側への移動とヘッダーリンクは利用できる。

区間ごとの必要映像をstart/endで管理し、現在位置と移動先の間で未取得の範囲に入る直前に止める。雑誌・モニター待機など、重なる区間の依存ファイルも一緒に準備する。未取得の前半があっても、取得済みの後半から本文へ進む操作は妨げない。完了後に以前のスクロール入力を再実行しない。

本文から初めて街へ戻るときは、街の先頭75%が既に使えるか確認する。不足する場合のみ、その戻り操作用に街を明示取得して保持する。通常の起動時の75%読み込み方針は維持する。初期表示を飛ばした往路の位相は0として確定し、逆方向でも街のカメラ位置をスクロールから計算する。

## ロゴと明示的な再開始

左上のロゴ、01の場面選択、本文の「もう一度、店舗を巡る」は共通のrestartJourneyを呼ぶ。本文の先頭へ戻す動作や、未取得区間を逆順にたどる動作とは分ける。メニュー・ハッシュ・入口位相・過去のスクロール要求・境界待機・投影状態を解除し、スクロール位置0と街の再生時刻0を設定する。

完了済みBlobは保持し、未完了の転送だけをcancelPendingで中断する。入口のロード判定は独立したentranceCycleで再開始する。街のBlob取得が途中だった場合もsourceVersionでソース制御を更新し、キャンセル済みのPromiseを待ち続けない。ネイティブ先読み済みの街は不要にソースを付け替えない。実エラーからの再開始では取得セッションも再試行する。

# CAR PRODUCE ONE — サイト体験の設計案

検討段階の提案。サイトの実装、Blenderの変更、本番レンダーはまだ行わない。数値は初期の演出設計値であり、ブラウザー上の試作で調整する。

## 1. 全体の方向

夜の街から店舗へ入り、仕事の雰囲気を感じ、モニターを通って情報を探せるサイトへ移る。入口は映画的に、店舗では落ち着いて読めるように、本編ではサービスや連絡先を使いやすくする。

視覚の中心は、雨の路面、車体の反射、黒い壁、木、金属、ガラス。前景UIは薄い罫線、整った文字組み、暗い半透明の情報面で揃える。ノイズはモニターとの境界を示す瞬間に集中させる。

本編の主目的は、ひとまず「整備について相談・問い合わせができること」として設計する。サービス名、対応範囲、実例、所在地、営業時間、連絡方法は実際の情報で確定する。

## 2. 一続きの体験

| 場面 | 背景の動き | 前景の役割 |
| --- | --- | --- |
| 最初の画面 | 夜の都市を自動で巡回 | ロゴ、短いコピー、スクロール案内、本編への入口 |
| 店舗へ向かう | スクロールに応じて到着・降車 | 文字を引き、店舗を見せる |
| 工具台へ | 店内へ入って視線が整う | 章名だけを小さく出す |
| 工具台で読む | 微かな揺れの専用ループ | 仕事への姿勢、相談できること |
| 雑誌へ移動 | 情報面が消え、カメラが移る | 空間を見せる |
| 雑誌で読む | 微かな揺れの専用ループ | 車との付き合い方、実例・読み物への導線 |
| PCへ向かう | デスクを回り込む | 情報面を引き、本編への期待を作る |
| モニターへ接近 | 画面が大きくなる | モニター上に本編と共通のロゴ・見出し |
| モニターを越える | 短いノイズと画面の受け渡し | 映像から実際のページへ切り替える |
| サイト本編 | 通常のページスクロール | サービス、整備の記録、会社案内、アクセス、問い合わせ |

90秒は制作中の動線確認用の尺。閲覧者に90秒の待機を要求する設計にはしない。サイト用には移動の見せ方と区間の尺を再編集し、読む時間は閲覧者に任せる。

## 3. 時間を分けて制御する

時間の役割を三つに分ける。

1. スクロールの進行：街から店舗、工具、雑誌、PCへ進む位置。
2. 待機中の時間：街の巡回と、読む場所での小さな揺れ。
3. 一度だけ走る短い演出：文字の出入り、ノイズ、画面の受け渡し。

スクロールを止めても、読む場所の揺れは続く。一方、ノイズは短時間で収まり、境界付近で止めたまま点滅し続ける状態にはしない。

スクロール量と映像内の時刻を、90秒全体に一様に割り当てない。移動区間と読む区間それぞれに必要なスクロール距離を持たせる。早く進む入力では目標位置を更新し、過剰な慣性を積み上げない。移動の自然さと追従の速さは試作で確認する。

## 4. 街ループから店舗への切り替え

現在の48秒ループを待機中の背景として活かす。長く眺めても広告や建物が変化する利点を残す。

ただし、ループの任意の時点と到着シーンの先頭は、街の建物配置まで一致するわけではない。現状の「同じ開始地点からの0.5秒クロスディゾルブ」だけを、そのまま全位相で成立すると見なさない。

最初のスクロール入力を受けたら、約0.45〜0.7秒の短い接続を使う。車内のフレームを視覚的な基準にし、窓外の街を少しだけぼかし、暗部とガラスの反射の中で到着シーンへ受け渡す。48秒の終わりまで待たせない。

接続中の入力は次の目標位置として受け取り、接続終了後に反映する。ループ映像と到着映像は、表示する前に必要なフレームを準備する。準備が間に合わない場合は現在の映像を維持し、本編へ直接進む導線も使えるようにする。

位相0％・25％・50％・75％などから離脱する試作を作り、窓外の二重像や道路の飛びが気になる場合は、接続用の短い映像を追加制作する。

## 5. 工具台・雑誌で読む体験

読む場所には、入口と出口を定めた4〜6秒程度の専用ループを用意する。現在の長い映像の一部を単純に切り取るだけでは、揺れと背景の動きが継ぎ目で一致する保証がない。カメラ、見えている交通、照明、反射も含めて周期を揃える。

移動映像から読むループへは、姿勢を揃えた短い接続を使う。カメラが落ち着いてから約0.2秒後に文字を出す。見出しを先に、本文を少し遅らせ、全体で約0.25〜0.35秒。浮き上がる距離は8〜12px程度とする。

次へスクロールしたら、情報面を約0.12〜0.2秒で引いてから移動を見せる。細かく前後にスクロールしても、カードが点滅するように出入りしないよう境界に余裕を持たせる。

### 工具台の情報面

配置案は画面左下、幅320〜420px程度。工具の輪郭と手元のディテールが見える位置を選ぶ。見出し1本、短い本文2〜3行、リンク1つに絞る。

コピー案：

> 一台ずつ、きちんと向き合う。
>
> 小さな違和感も、気軽にご相談ください。
>
> 私たちの仕事を見る

リンクを押した場合は、詳細を読める面を開くか、本編の該当箇所へ進む。読む途中で次の文章へ自動的に切り替えない。閉じたときは同じ場面に戻る。

### 雑誌の情報面

配置案は左上の暗い余白。雑誌の表紙を覆わないことを優先する。ここでは工具台と同じ整備説明を繰り返さず、車との付き合い方や実例につなぐ。

コピー案：

> 車と過ごす時間を、もっと。
>
> 日々のことも、これからのことも。
>
> 整備の記録を見る

掲載する実例が整っていない段階では、実際に提供できる内容に合わせて導線とコピーを変更する。

### 情報面の質感

黒〜チャコールをベースにした曇りガラス。背景を少し残しつつ、本文の背後は十分に暗くする。角はわずかに丸め、輪郭には細いハイライトを入れる。背景の車や照明が動いても、本文の読みやすさが変わりすぎない濃度を選ぶ。

## 6. モニターへの接近

PCへ向かい始めたら、情報面を完全に引く。モニター自体が次の入口になる。

モニター内は、本編冒頭と共通のロゴ、背景色、文字組みを使う。複雑なメニューを最初から詰め込まず、中央のロゴと短い見出しを中心にし、画面比率が変わってもつながりを作りやすくする。

最終のモニター用テクスチャは、本編のデザインを先に決めてから作る。映像の画面と実際のHTMLで、ロゴの位置、余白、文字の改行、背景色が突然変わらないようにする。

## 7. ノイズとHTMLへの受け渡し

接近の後半を四段階で作る。

| 段階 | 見え方 |
| --- | --- |
| 画面が視界の約半分 | ごく薄い粒状感。画面の光が少し強まる |
| 約7割 | 一度だけ短い水平の揺らぎ。目立ちすぎないRGBのずれ |
| 約9割 | 画面の四隅に合わせて、本編と同じHTMLの見た目を重ねる |
| 全面 | モニターの縁が外へ抜け、ノイズが収まる。ナビゲーションとボタンが現れる |

ノイズの初期値は、粒状感の不透明度2〜4％、RGBのずれ1〜2px程度、目立つ揺らぎは約0.1〜0.18秒を一度だけ。全面的な強い明滅を使わず、画面の中から外へ移る瞬間を示す。

ノイズを常時かけると、本編までざらついて読みにくくなる。切り替えが終わったら文字とボタンは鮮明にする。ノイズの強さ、粒の大きさ、色ずれは実画面で調整する。

映像とHTMLは重ねる期間を持ち、モニターの四隅に合わせて位置と遠近感を追従させる。全面になる直前に画面の比率・余白を吸収し、操作可能なHTMLへ切り替える。ナビゲーションなど細かい要素は全面に切り替わってから表示し、映像内の小さな文字と二重にならないようにする。

## 8. モニターに入った後

本編は、店舗の黒・木・金属を引き継いだ落ち着いたページにする。背景はチャコール、文字はアイボリー、アクセントは車体から拾った暗い青。暖色は写真と小さな光に使う。

最初はモニターに映っていたロゴと見出しをそのまま受け取る。少し落ち着いてからヘッダーと主な導線が現れ、以降は通常のページとして読める。

本編の構成案：

1. 冒頭：店名、短いメッセージ、「サービスを見る」「相談する」。
2. サービス：実際に対応している仕事を、内容と写真で紹介。
3. 整備の記録：実例の写真、相談内容、行った対応。事実に基づいて掲載。
4. 私たちについて：店舗や人の雰囲気、仕事への考え方。
5. アクセス・営業時間：実際の住所、地図、連絡先。
6. 問い合わせ：電話・フォームなど、実際に受け付けられる方法。

写真の大きさ、余白、文字の左右配置に変化を付け、誌面のように読める構成にする。サービスの説明や問い合わせの場面では操作を分かりやすくする。

本編に到達した後、上にスクロールしただけで再び3D映像へ引き戻さない。「店舗ツアーを見る」から明示的に戻れるようにする。サービスの詳細や連絡先は、演出を通らず直接開けるようにする。

## 9. 共通のナビゲーション

映像中も、店名と「本編へ」の入口を小さく残す。章の位置は細い目盛りと短いラベルで示す。工具・雑誌・本編へ直接移動できる章メニューを用意する。

映像内ではスクロールを戻すと前の場面へ戻れるようにする。待機ループへ戻る際は、記憶した位相または姿勢の近い接続点を使い、景色が突然先頭へ飛ぶのを避ける。

再訪問では本編を優先し、演出を見たい場合にツアーを再生できる構成を候補とする。戻り方と再訪時の初期表示は試作で確認する。

## 10. 文字・色・細部の演出

- 英字の店名は輪郭の整った書体で見せ、日本語本文は読みやすさを優先する。
- 見出しは短く、本文は落ち着いた大きさと行間で読む。大きな文字は入口や章の切り替わりに集中させる。
- ボタンは細い輪郭と小さな矢印を基調とし、操作時に線や矢印が少し動く。
- 通常の表示切り替えは約0.18〜0.3秒、章の情報面は約0.25〜0.35秒を初期値とする。
- 音を加える場合は初期状態を無音とし、利用者が有効にしたときだけ街の環境音や小さな操作音を使う。
- 映像を主役にする区間では文字を減らし、読む区間ではカメラを落ち着かせる。

## 11. スマートフォンと軽量な表示

横長の映像を単純に中央で切り取るだけでは、工具・雑誌・モニターが画面外へ出る。縦画面用の構図を制作し、主要な物は上側、情報面は下側に置ける余白を確保する。

本文や問い合わせは通常のタッチ操作で使えるようにする。動きを減らす設定では、静止画と短いフェードで同じ情報へ進めるようにする。映像が準備できない場合も、本文や連絡先を利用できる状態を保つ。

初期表示では街の待機映像、静止画、最小限のUIを準備し、次に必要な区間を先読みする。重い映像がすべて揃うまでサイト全体を待たせる設計にはしない。

## 12. 制作方式と必要な素材

背景はBlenderで書き出した映像、本文・メニュー・ボタンはHTMLで構成する。ノイズと画面の受け渡しに必要な描画処理を追加する。技術スタックの確定は、スクロール追従・逆方向の移動・端末での再生を試作してから行う。

必要な素材の単位：

- 街の待機ループ。
- 任意のループ位相から到着へ移る接続。
- 到着・降車・入店の移動区間。
- 工具台の読むループと入口・出口。
- 工具台から雑誌への移動。
- 雑誌の読むループと入口・出口。
- デスクを回り込んでPCへ向かう区間。
- モニター接近と、画面の位置を追うための四隅のデータ。
- 本編冒頭と同じデザインのモニター画面。
- 縦画面用の対応素材と、各区間の静止画。

現在のv17は空間・動線・配色の基礎として使用する。専用の読むループ、任意位相からの接続、モニターの画面受け渡しは、サイト向けの追加制作項目。

## 13. 実装前に作る試作

最初に三つの短い試作を作る。

1. 街ループの任意の時点でスクロールを始め、到着へつながる試作。
2. 工具台で背景が微かに揺れ、情報面を読み、スクロールで退出する試作。
3. モニター内の本編画面へ近づき、短いノイズを経て操作可能なHTMLへ切り替わる試作。

確認するのは、速いスクロール、逆スクロール、境界での停止、途中でのメニュー操作、映像準備待ち、縦画面、動きを減らす表示。接続と読書体験が成立してから、全区間の本番レンダーと本編制作を進める。
